# /aside — タスクを汚さず質問に答える

## 使い方

```text
/aside <質問>
```

例:
```text
/aside src/solver.py の RHS、なぜ係数 2 が掛かってる?
/aside この式の次元、合ってる?
/aside numpy.einsum の 'ij,jk->ik' は行列積と同じ?
/aside Hermitian と self-adjoint の違いは?
```

## あなた (= Claude) の手順

### Step 1: 現在タスク状態を凍結

返答前に**頭の中で**以下を記録する:

- 進行中のタスク (どのファイル・どの機能・どの bug を扱っているか)
- 直前に行っていた操作 (どの tool を呼ぶ予定だったか)
- 次に予定していたアクション

ファイル・コード・状態は**一切変更しない**。

### Step 2: 質問に直接答える

- 結論を 1 文目で述べる ([.dev/SOUL.md](../../.dev/SOUL.md) "結論を先に述べる")
- 必要なら 2〜3 行の補足のみ
- 不確かさは定量化 ([.dev/SOUL.md](../../.dev/SOUL.md) "不確かさを定量化する")
- ファイルを変更する誘惑があっても**しない**
- 質問が大きすぎて短答できないなら、その旨を述べ「正規のタスクとして取り上げますか?」と確認

### Step 3: 元のタスクに戻る

返答の最後に**短く**「元のタスクに戻ります」と明示し、Step 1 で凍結したタスクの直前操作を再開する。

## してはいけないこと

- ファイル変更、コード変更、コミット
- 長い説明 (返答 ≤ 5 行が目安)
- 元のタスクへの「ついで」修正
- 質問が脇道でないと判断したのにファイルを触る (その場合は `/aside` を解除すべき旨をユーザに伝える)

## 返答テンプレ

```markdown
[1 文の結論]
[必要なら 2〜3 行の補足]

ファイルは何も変更していません。元のタスク (X) に戻ります。
```
