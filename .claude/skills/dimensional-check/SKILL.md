# Dimensional Check Skill

物理式・数値計算コードの**単位と次元**を体系的に検証するためのスキル。

## When to Activate

- 新しい物理量 (速度、運動量、エネルギー、応力、振幅、…) を扱うコードを書く・変更する
- 物理レビュア (`reviewer-physical`) が一次レビューを行う
- 既存式から係数を削除・追加する変更が入る
- 単位系の異なるライブラリ間で値を受け渡す (例: cgs ↔ SI、自然単位 ↔ SI)
- フィッティング・回帰の係数物理意味を検証する

## Core Procedure

### Step 1: 記号テーブルを書く

変更箇所に登場する全ての記号について、SI 基本単位での次元を列挙する。

```text
記号      意味             SI 単位              次元 (M L T I Θ N J)
ψ        波動関数         m^(-3/2)             L^(-3/2)
H        ハミルトニアン   J                    M L^2 T^(-2)
ℏ        Dirac h          J·s                  M L^2 T^(-1)
m        質量             kg                   M
```

### Step 2: 演算子ごとの次元伝播を追跡

| 演算 | 次元への影響 |
| --- | --- |
| `a + b`, `a - b` | 次元一致が必要。違うと**エラー** |
| `a * b` | 次元は積 |
| `a / b` | 次元は商 |
| `a ** n` (n: 無次元数) | 次元は n 乗 |
| 微分 `d/dx` | 次元は `1/[x]` |
| 積分 `∫ dx` | 次元は `[x]` 倍 |
| 三角関数, exp, log の引数 | **無次元でなければエラー** |
| Fourier transform 周波数 | `t` の次元と相補 |

### Step 3: 等号両辺の次元一致を確認

実装したコードの各代入式について、左辺と右辺の次元が一致することを式変形で確認する。

```python
# 例: E = (1/2) m v^2
# 左辺: [E] = M L^2 T^(-2)
# 右辺: [m] · [v]^2 = M · (L T^(-1))^2 = M L^2 T^(-2)  ✓
```

### Step 4: 極限・対称性チェック

- 自由極限 (相互作用ゼロ) で式が知っている解析解に帰着するか
- 古典極限 (ℏ → 0, c → ∞ など) で対応する古典式に帰着するか
- 時間反転、空間反転、ゲージ変換などの対称性に対する振る舞いが正しいか

### Step 5: 異常検出

以下のパターンは**ほぼ確実にバグ**:

- `np.exp(x)` で `x` が物理量 (J や kg を持つ) — 規格化忘れ
- `1.0 / x` で `x` がゼロになる極限 — 発散の物理的意味を要確認
- 単位系混在 (eV と J、Å と m、cm⁻¹ と Hz) — 換算係数明示の有無
- 数値定数の hard-code (`6.626e-34` など) — 物理定数モジュールを使え

## Output (使用後の記録)

レビュー report 内で以下のフォーマットで結果を残す:

```markdown
### dimensional-check (`src/solver.py:42` の式 H_eff = ...)
- ✓ 記号テーブル作成 (m: M, v: L T^(-1), ℏ: M L^2 T^(-1))
- ✓ 両辺次元一致: M L^2 T^(-2) (= エネルギー次元)
- ✓ 古典極限 ℏ → 0 で正しい古典 EOM
- ⚠ 注意: 引数 `np.exp(-βH)` の β は 1/J でなければ無次元化失敗
```

## NG パターン (絶対避ける)

- 次元解析を**書かずに**「単位は合ってると思います」とコメントする
- 単位系を**暗黙に**仮定する (cgs/SI を明示しない)
- 物理定数を**マジックナンバー**で書く
