## 1. Fig.9 — ΔlnL スペクトル

### 1.1 対象

論文 p.13 (**PDF 14 ページ目**、`PAGE_INDEX = 13`)。3 つの halo モデル
(NFW-ρ^2.5 / ρ² / ρ¹) の `ln(L) - ln(L_no-halo)` が 13 ビン分描かれている。
**本研究の baseline は NFW-ρ² なので、赤い丸の系列のみを読む。**

### 1.2 手順

1. PDF を **400 dpi** でラスタ化する
2. 軸の目盛から画素 → データ座標の写像を決める
3. **濃い赤** (`r-g > 150` かつ `r-b > 150` かつ `r > 180`) の画素のみ抽出する。
   細い薄赤線は MCMC chain の**上位 95% 境界**であり best-fit ではないので除外する
4. marker (白抜き丸) の中心を **matched filter** で求める。
   丸の外径は実測 32 px なので、**半径 12〜17 px の円環テンプレート**を
   marker 列の周辺で縦に走査し、円環上に載る濃赤画素が最多の行を中心とする

### 1.3 軸較正値 (400 dpi での画素座標)

| 軸 | 目盛 | 画素 |
| --- | --- | --- |
| x (log) | 1 / 10 / 100 / 1000 GeV | col 1028 / 1527 / 2027 / 2525 |
| y (線形) | 100 / 50 / 0 | row 654 / 1063 / 1471 |
| 枠 | left/right/top/bottom | 928 / 2526 / 490 / 1635 |
| 凡例除外域 | 右上 | col ≥ 1780 かつ row ≤ 830 |

**1 単位 ΔlnL = 8.17 px**、すなわち **1 px = 0.1224 ΔlnL**。

### 1.4 検証

読み取り点を元図に緑の十字で重ね描きし、**全13ビンで丸の中心に一致することを目視確認済み**。

### 1.5 棄却した方式 (再導入禁止)

**「濃赤クラスタの上端と下端の中点を取る」方式は誤り。**
曲線が急峻なビン (1.5 GeV など) で、列窓 (±6 px) に立ち下がり部分が入り込み、
**ΔlnL が 4〜5 下振れする**。重ね描き検証で発見した。

### 1.6 精度 — **σ に直すと高エネルギーで壊滅的に悪化する**

有意度は `σ = sqrt(2 ΔlnL)` で換算する (Wilks の定理、自由度 1)。
**この平方根がゼロ近傍で急峻**なため、同じ 1 px の読み取り誤差でも
ΔlnL が小さいビンでは σ が大きく動く:

```
dσ/dΔlnL = 1 / sqrt(2 ΔlnL)     →  ΔlnL → 0 で発散する
```

marker 位置 ±2 px を仮定した場合 ([ASSUMPTION]、1 px 未満の精度は未検証):

| E [GeV] | ΔlnL | σ | dσ/dΔlnL | σ の誤差 | 相対誤差 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1.5 | 102.10 | 14.29 | 0.070 | 0.017 | **0.1%** |
| 2.5 | −0.10 | 0.00 | 発散 | — | — |
| 4.3 | 20.83 | 6.45 | 0.155 | 0.038 | 0.6% |
| 7.3 | 79.58 | 12.62 | 0.079 | 0.019 | 0.2% |
| 12.3 | 93.29 | 13.66 | 0.073 | 0.018 | 0.1% |
| 20.8 | 102.10 | 14.29 | 0.070 | 0.017 | **0.1%** |
| 35.1 | 50.94 | 10.09 | 0.099 | 0.024 | 0.2% |
| 59.2 | 23.28 | 6.82 | 0.147 | 0.036 | 0.5% |
| 100.0 | 7.98 | 3.99 | 0.250 | 0.061 | 1.5% |
| 168.9 | 6.39 | 3.57 | 0.280 | 0.069 | 1.9% |
| 285.3 | 1.24 | 1.58 | 0.634 | 0.156 | 9.9% |
| **481.9** | **0.14** | **0.53** | **1.871** | **0.440** | **82.4%** |
| **814.0** | **0.27** | **0.73** | **1.373** | **0.404** | **55.5%** |

**感度は 20.8 GeV と 481.9 GeV で 27 倍違う** (0.070 vs 1.871)。

### 1.7 この精度限界から言えること・言えないこと

- ✅ **主要域 (1.5〜169 GeV) の本研究/Totani 比 1.29〜1.93 は堅い** (σ の誤差 ±0.07 以内)
- ❌ **481.9 GeV の比は使えない**。Totani σ が **[0.00, 0.88]** で
  **ゼロを含むため比の上限が決まらない**。「比 2.88」と書いてはいけない
- ❌ **814.0 GeV も使えない**。Totani σ が [0.20, 1.01] で比は 1.15〜5.8 の幅
- ❌ 2.55 GeV は Totani ΔlnL が負なので σ = 0。**比を定義できない**

### 1.8 ⭐ 最も重要な直感: **読み取りは難しくなっていない**

高エネルギー側で「読み取りが難しくなる」わけではない。**読み取り精度は全ビンで同一**である
(±2 px = ΔlnL で ±0.245)。変わるのは **σ に換算する計算のほう**である。

同じ ±0.245 の誤差が σ に与える影響:

| E | ΔlnL の読み | σ | ΔlnL が +0.245 ずれたら | σ の変化 |
| --- | --- | --- | --- | --- |
| 20.8 GeV | 102.10 | 14.29 | 102.35 → σ = 14.31 | **+0.02 だけ** |
| 481.9 GeV | 0.14 | 0.53 | 0.39 → σ = 0.88 | **+0.35 (66%)** |

**同じ ±0.245 なのに、σ の動き方が 17 倍違う。**

理由は平方根の形だけである:

```
sqrt(100) = 10.00   sqrt(102) = 10.10   → ほとんど変わらない
sqrt(0.10) = 0.32   sqrt(0.35) = 0.59   → 2 倍近く変わる
```

**平方根は、元の数がゼロに近いほど答えが敏感に変わる。**
ΔlnL は 20.8 GeV の 102 から 481.9 GeV の 0.14 まで約 700 分の 1 に落ちるので、
高エネルギー側だけがこの「拡大鏡」に乗ってしまう。

### 1.9 ⚠️ よくある誤った説明 (発表で言わないこと)

> ❌「エネルギー軸が log 表記だから、高エネルギー側で読み取り誤差が大きくなる」

**これは誤り**。理由は 3 つ:

1. **x 軸の読み取り誤差は関与しない。** 13 ビンの中心エネルギーは既知なので、
   その列を狙って読む。x の位置を測定しているわけではない
2. **高エネルギーで値は「大きく」ならず「小さく」なる。** ΔlnL は
   20.8 GeV の 102 から 481.9 GeV の 0.14 まで**約 700 分の 1 に落ちる**
3. **真因は y 軸側の平方根**。ΔlnL は線形軸で読み取り誤差は全ビン一律 (±0.245)。
   それを `σ = sqrt(2 ΔlnL)` に通すとき、ゼロ近傍で傾きが発散するため
   σ の誤差だけが跳ね上がる

> ✅ 正しい説明: 「**図の読み取り精度はどのエネルギーでも同じ**。ただし有意度は
> ΔlnL の**平方根**で決まり、平方根はゼロの近くで急に立ち上がる。高エネルギー側では
> ΔlnL がほぼゼロまで落ちるので、同じ読み取り誤差でも有意度が大きく動いてしまう。
> だから高エネルギー 2 ビンの比は信用できない」

**なお「1 px あたりの有意度の変化量が高エネルギー側で大きくなるから、
1 px ずれるだけで大きく影響する」という言い方は正しい。**
これは `dσ/dΔlnL = 1/sqrt(2 ΔlnL)` が増大することそのものを指している。
誤りなのは、その原因を**横軸 (エネルギー) が log であること**に帰する部分だけである。

## 2. Fig.14 下段 — 21 GeV の ICS マップ

### 2.1 対象

論文 p.17 (**PDF 18 ページ目**、`PAGE_INDEX = 17`)。下段 3 枚が GALPROP の
ICS 成分を標的光子場ごとに分けたマップ (optical / infrared / CMB)。

### 2.2 手順と較正値

マップは **PDF に 960×961 の元画像として埋め込まれている**ので、
xref から直接取り出す (**ラスタ化・再標本化の誤差ゼロ**)。

| パネル | xref | カラーバー x 範囲 (400 dpi) | 目盛分割 | 最大値 [ph cm⁻²s⁻¹sr⁻¹MeV⁻¹] |
| --- | --- | --- | --- | --- |
| ICS optical | 904 | 572–1236 | 15 | 3.0e-13 |
| ICS infrared | 905 | 1372–2035 | 10 | 1.0e-13 |
| ICS CMB | 906 | 2171–2835 | 25 | 5.0e-14 |

カラーバーの行範囲は 400 dpi で row 1426–1441。
**目盛は等間隔で、左端 = 0・右端 = 最大値の線形スケール**
(目盛本数を実測し、ラベル間隔と整合することを確認済み)。

画素 → 銀緯: **上端 = b +60°、中央行 = b 0°、下端 = b −60°**。

### 2.3 検証

**灰色帯 (銀河面除外域 |b| < 10°) の位置で緯度較正を検証済み**:

- 灰色帯の中心 = パネル高さの **0.5000** (期待 0.5) ✅
- 灰色帯の幅 = パネル高さの **0.1654** (期待 20/120 = 0.1667、誤差 0.8%) ✅

### 2.4 精度限界 — 銀河面近傍は飽和する

銀河面近傍はカラースケール上限に張り付く。判定は
**「値が vmax の 98% 以上」**で行う (LUT 最上位色との一致判定では検出漏れする)。
飽和率 1% 以上の緯度帯は比較から除外し、**実質 |b| ≳ 20° のみ比較可能**。

### 2.5 ⚠️ 未解決の食い違い

Fig.14 から読んだ ICS 合計の ROI 平均 (**1.78e-13**) が、
**Fig.6 から換算した値 (4.16e-13) と 2.3 倍食い違う**。
銀河面近傍の飽和による下振れが一因だが全部は説明できない。

**ただし形の結論はこの食い違いに依存しない** (|b| = 25° で規格化して比較しているため)。
絶対値を論じるときだけこの未解決点を明示すること。

### 2.6 得られた結論 (2026-07-24)

**本研究の ICS は Totani より緯度方向に平坦。**

| ICS 成分 | \|b\| 25°→55° の落ち込み (Totani) | 同 (本研究) | 平坦さ超過 |
| --- | ---: | ---: | ---: |
| optical | 2.79 倍 | 2.03 倍 | 1.37 |
| infrared | 2.65 倍 | 1.98 倍 | 1.34 |
| CMB | 2.09 倍 | 1.22 倍 | 1.71 |

平坦な ICS は等方成分と数学的に区別できないため、fit が等方成分の分を ICS に
付け替える。**これが iso が Totani の 1/200 に潰れる機序**であり、
緯度帯対照実験 (ICS に自由度を与えたときだけ iso が戻る) と完全に整合する。

## 3. Fig.6 — 成分スペクトル

`code/digitize_totani_fig6_v2.py`。縦軸は **E²dN/dE [MeV cm⁻²s⁻¹sr⁻¹]**、
範囲 1e-6〜1e-2。dN/dE への換算は `E²dN/dE / E_MeV²`。

v1 (`digitize_totani_fig6.py`) は「色が一致する画素の密な塊」を拾う方式で、
**誤差棒と点線も同色**のため高エネルギー側で誤差棒の先端を拾う失敗があった。
v2 は連結成分の**横幅**でマーカーと誤差棒を分離する (誤差棒は幅数 px、
マーカーは数十 px)。黒は gas (□) と ICS (⬠) の 2 種類あるので**上端の幅**で見分ける。

## 4. 共通の教訓

1. **読み取り点は必ず元図に重ね描きして目視検証する。** Fig.9 の下振れ 4〜5 も
   Fig.14 の緯度較正も、この工程で確定した
2. **図に誤差を入れずに比だけ書かない。** 意味のない数字が意味ありげに見える
   (481.9 GeV の「比 2.88」がその実例)
3. **表示条件でデータを黙って落とさない。** 落とすなら図の中に理由を書く
   (2026-07-24 に比パネルの右端を消して誤読を招いた)
4. **PDF に元画像が埋め込まれていないか先に確認する** (`page.get_image_info(xrefs=True)`)。
   あればラスタ化を経ずに読めて誤差がゼロになる
5. **本機は RAM 5.8 GB。** 最近傍色探索のような総当たりは必ず分割して回す
   (一括だと 92 万画素 × 665 色 × 3 で 13.7 GiB を要求して落ちた)
