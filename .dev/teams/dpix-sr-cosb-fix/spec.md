# Spec — DPIX_SR の cos(b) 立体角補正欠落の修正

Tier: M (物理 + 数値の両観点が関わるため)。MAX_ITER: 5。

## 背景・問題

`code/mcmc_fit_all_bins.py:125`:

```python
DPIX_SR = (np.pi / 180.0) ** 2  # 1°ピクセルの立体角 [sr]
```

解析グリッドは (l, b) 緯度経度グリッド(`L_BINS`/`B_BINS`、1°刻み、ROI `|b|=10°〜60°`)。
1ピクセルの真の立体角は `ΔΩ(b) = Δl・Δb・cos(b)` であり、`(π/180)²` はb=0でのみ正しい。
現状は全ピクセルに同一定数を適用しており、`|b|=60°`では真の立体角を最大2倍過大評価する
(cos(10°)=0.985, cos(30°)=0.866, cos(55°)=0.574, cos(60°)=0.500)。

このDPIX_SRは`build_templates_for_bin()`内でgas/ICS/halo全テンプレートに掛かる
(`code/mcmc_fit_all_bins.py:249,250,274`)。全テンプレートに同一に掛かるため相対比は
保たれるが、各領域**内部**でもcos(b)は大きく変化するため、緯度方向になめらかに変化する
系統的な過大/過小評価を生み、それをNFWハロー(これ自体もbに応じてなめらかに変化する
テンプレート)や他の柔軟なテンプレートが部分的に肩代わりしている可能性がある。これは
`.dev/teams/galprop-gas-ics-separation/`の物理・数値レビューが「次元解析」
(単位がsrであることの確認)は行ったが、「グリッド全域で数値が正しいか」は検証していない
盲点([[verdict.md]]参照)。

現在、gas/ICS分離後もTotani(2025)報告値(13-19σ)を上回る非物理的な高有意度(全13ビンで
最大28.5σ)が残存しており、この修正がその一因である可能性を検証する。

## 修正対象ファイル(DPIX_SR定義箇所、grep済み)

1. `code/mcmc_fit_all_bins.py` — **本番/headlineパイプライン。最優先**
2. `code/mcmc_fit.py` — Bin6専用の旧スクリプト。過去に`VALID_MASK`修正を同期適用した実績あり(HANDOFF.md参照)、同様に同期する
3. `code/mcmc_fit_all_bins_galprop_webrun_check.py` — 却下済みwebrun比較用(系統誤差チェック目的で残置)。同期する
4. `code/mcmc_fit_all_bins_galprop_webrun_v2.py` — `mfa.DPIX_SR`を参照するのみなので#1の修正が自動反映されるはずだが、グリッド形状の整合を確認すること

## 修正方針

- `DPIX_SR`をスカラー定数から、グリッド形状(L_C×B_C、shape=(120,120)相当)に一致する
  配列 `DPIX_SR_GRID = (np.pi/180.0)**2 * np.cos(np.radians(BG))` に置き換える
  (`BG`は各ファイル内の緯度グリッド変数名に合わせる)
- 変数名は「もう定数ではない」ことが分かるよう`DPIX_SR`から改名してよい(例: `PIX_SOLID_ANGLE_SR`)。
  ただし外部から`mfa.DPIX_SR`のように参照している箇所(#4)があるため、改名する場合は
  参照側も全て追従させ、grep漏れがないことを確認する
- `calibrate_nfw_norm()`(`code/mcmc_fit_all_bins.py:204-222`)は`DPIX_SR`が分子分母に
  同一に現れ代数的に約分される設計([ASSUMPTION]従来はスカラーなので任意の値で約分可能)。
  配列化した場合も、同じ参照ピクセル(`ib_ref, jb_ref`)の値を分子分母双方で使えば
  数学的に約分は成立するはずだが、実装がその通りになっているか必ず確認すること
  (配列のブロードキャストで意図せず異なる形状のまま演算されないか等)
- 勾配計算(`neg_log_likelihood_and_grad`等)はテンプレート配列(`T_k`)そのものに対する
  微分であり、`T_k`の内部構成(DPIX_SRがスカラーか配列か)には依存しないはずである。
  この前提が成り立つか(解析勾配コードがDPIX_SRを直接参照していないか)確認すること
- NFWのJ-factor視線積分(`nfw_j_map()`)自体は3次元の物理座標変換であり、この立体角
  バグとは独立(修正不要)。混同しないこと

## 検証・合格条件

1. **物理**: 修正後のテンプレートで次元解析(counts整合)・cos(b)の値がb=0で(π/180)²に
   一致する極限チェック・対称性(b→-bで不変)を確認する
2. **数値**: 修正前後でBin6の複数初期値からの収束一致度(fun_spread)が悪化しないこと、
   解析勾配と有限差分の一致を再確認すること(N-1修正時と同じ手法)
3. **再計算**: 修正版で以下を再実行し、修正前(headline: `results/mcmc_allbins_gasICS_v1/`)
   との比較を定量的に示す。上書きせず新規ディレクトリに保存する
   - 全13ビンMCMC同時フィット → `results/mcmc_allbins_gasICS_v2_cosb/`
   - 領域A/C f_halo共有LRT検定(`code/diagnose_regionAC_lrt_all_bins.py`相当) →
     同ディレクトリ内に保存
4. **報告**: 少なくともBin6のf_halo・有意度が修正前後でどう変わったか、全13ビンスペクトルの
   形がどう変わったか、領域A/C LRT検定の有意度がどう変わったかを定量的に報告する。
   「これでTotani報告値と一致した」等の断定は数値が実際にそうなった場合のみ書く
5. 実行環境(seed, commit hash, python/numpy/scipy version)を結果jsonに埋め込む
   ([[reproducibility-stamp]]相当)
