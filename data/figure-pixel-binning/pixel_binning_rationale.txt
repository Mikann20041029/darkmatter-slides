# ピクセル幅 1°×1° と「2次元化（binning）」の方法 — 基礎説明
# 想定質問: 「イベントリスト(l, b, E の光子リスト)からどうやって2次元スカイマップを作るのか」
#           「なまし（スムージング）はかけているのか」「なぜ 1° なのか、Totani の 0.1° と何が違うのか」
# 関連コード: code/all_bins_nfw_fit.py:57-64,127-133 / code/plot_skymap_all_subtracted.py:187,328

## 1. 2次元化の方法: 単純な2次元ヒストグラム（なまし＝スムージングは「かけていない」）

生データは「1イベント = 1光子の (銀経 l, 銀緯 b, エネルギー E)」のリスト（CSV、約 780 週分）。
これを2次元スカイマップにする手順は以下の通りで、**ガウシアン等のスムージングカーネルは
一切適用していない**:

  1. (l, b) 平面を 1°×1° の格子（bin）に分割する
     - 本解析: `np.arange(-L_MAX + PIX/2, L_MAX, PIX)` で格子中心を生成 (PIX = 1.0°)
       (`all_bins_nfw_fit.py:49,58-60`)
     - 別経路のスカイマップ生成では `np.histogram2d(l, b, bins=[L_BINS, B_BINS])`
       を直接使用 (`plot_skymap_all_subtracted.py:187,328`)
  2. 各光子をその (l, b) が属する格子セルに割り当て、セルごとに光子数をカウントする
     （`assign_pixel()`: `np.floor((l + L_MAX)/PIX)` で整数インデックス化 → `np.add.at` で積算、
     `all_bins_nfw_fit.py:127-133,171`）
  3. 得られた "1 pixel = 1 セルあたりの光子数" の2次元配列をそのまま `pcolormesh` で表示する
     （補間 `interpolation=` オプションは使用せず、セル境界をそのまま描画）

→ つまり「なまし方」は **最近傍ビニング (nearest-bin histogram) のみ**であり、
  ピクセル間の値を平均化・畳み込みするような後処理（Gaussian smoothing 等）は行っていない。
  [解釈] Totani は構造化バブルテンプレート構築時に Gaussian smoothing (σ=1°) を適用しているのに対し
  (§3.1 p.6、`bin3_bubble_template_rationale.txt` 参照)、本解析はテンプレートを含め
  どの段階でも smoothing を適用していない、という点が明確な手法差である。

## 2. ピクセル幅 1°×1° の内訳（Totani の 0.1° との数値比較）

  - 本解析: 1°×1° → ROI (|l|≤60°, 10°≤|b|≤60°) を 120×120 グリッドでカバー
    = 14,400 セル/ビン × 13 エネルギービン = 187,200 セル
    (`write_all_notes.py:118` のスライドノートと整合)
  - Totani (2025): 0.125°×0.125° (`∆lp = ∆bp = 0.125°`, §2.1 p.3 原文確認済み) →
    同じ ROI を 960×960 グリッドでカバー = 921,600 セル/ビン
    ("resulting in 960×960 pixels in the ROI including the disk region")
  - 比: 本解析のピクセル面積は Totani の (0.125°/1°)⁻² = (8)² = **64 倍**粗い
    （1 セルに Totani の 64 セル分の光子が積算される。`960/120 = 8` がピクセル幅比に一致）

## 3. 1° で十分と言える理由（解像したい物理スケールとの比較）

- **NFW シグナルの空間スケール**: J-factor マップは銀河中心方向 (l=b=0) にピークを持ち、
  スケール半径 r_s = 21 kpc・太陽-GC 距離 D_sun = 8 kpc から、信号が緩やかに変化する
  角スケールは arctan(r_s / D_sun) ≈ arctan(21/8) ≈ **69°** のオーダー
  （[解釈] つまり「数十度」スケールで滑らかに変化する大域的構造であり、1° ピクセルで
  形状を追うのに不足はない）
- **Fermi-LAT の角度分解能 (PSF)**: 本解析で採用している値は「角度分解能 ≈ 0.1°（E ≳ 1 GeV）」
  (`write_all_notes.py:752`)。[解釈] 1° ピクセルは PSF (≈0.1°) の約10倍粗いため、
  個々の点源の形状を解像する用途には不向きだが、数十度スケールの拡散的ハロー構造の
  振幅フィットには影響しない
- **トレードオフとして失うもの**: 点源マスクの精度（本解析は半径 1° の円形マスクを使用、
  `all_bins_nfw_fit.py:89` — PSF スケール 0.1° に対して過大）。これは
  「点源近傍を広めに安全側でマスクしている」という保守的設計であり、NFW 振幅フィットの
  結論（全ビンで |S/N|<2.4、有意な超過なし）には影響しない

## 4. 計算コストとの関係

  - 1° (120×120=14,400 セル) と 0.1° (1200×1200=1,440,000 セル) では、
    NFW J-factor の視線積分（各セルで `N_LOS=500` 点の数値積分、`all_bins_nfw_fit.py:107-117`）
    の総計算量比は 64 倍。卒業研究の計算資源では 1° が現実的というのが
    `write_all_notes.py:159` の判断根拠と一致する

## 5. 結論（スライド用一文）

「2次元スカイマップは、(l, b) を 1°×1° のセルに区切って光子数を数えるだけの単純な
 ヒストグラムであり、ガウシアン等のスムージングは適用していない。Totani の 0.1° に対し
 ピクセル面積で 64 倍粗いが、解析対象である NFW ハロー構造の角スケール（~数十度）に対しては
 十分に細かく、振幅フィットの結論を左右しない」
