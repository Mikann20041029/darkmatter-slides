# Git / GitHub 管理の最小 howto

このテンプレートで Git / GitHub を使う目的は、複雑な開発をすることではなく、
研究ファイルの整理、変更履歴の記録、バックアップをしやすくすることです。

以下では、`main` ブランチだけを使う最小運用を前提にします。

## 1. 最初にやること

### 1-1. Git の初期化

`grad-AAA/` に移動して、次を実行します。

```bash
git init
git branch -M main
git add .
git commit -m "初回テンプレートを追加"
```

### 1-2. GitHub に新しいリポジトリを作る

GitHub 上で空のリポジトリを 1 つ作ります。  
README や `.gitignore` は GitHub 側で追加せず、空のまま作るのが安全です。

作成後、表示された URL を使って次を実行します。

```bash
git remote add origin <GitHubのリポジトリURL>
git push -u origin main
```

## 2. 日常の使い方

作業したら、基本は次の 4 手順だけで十分です。

```bash
git status
git add .
git commit -m "変更内容を短く書く"
git push
```

`git status` は、何が変更されたかを確認するために毎回見る癖をつけてください。
`git add .` を使うときは、不要なファイルまでまとめて追加していないか確認してください。  
不安なときは、`git add ファイル名` のように必要なものだけ追加する方が安全です。

## 3. 何を Git に入れるか

このリポジトリでは、次のようなものを Git で管理します。

- `code/` の解析コード、作図スクリプト、ノートブック
- `doc/` の研究メモ、打合せメモ、発表資料
- `ref/` の文献メモ、BibTeX、文献一覧
- `data/` のうち、再生成しにくい小さな表データや整理済みデータ
- `results/` のうち、共有したい解析結果や出力ファイル

## 4. 何を Git に入れないか

次のようなものは、原則として commit しません。

- `data/raw/` に置く生データ
- 外部から再取得できる配布データ
- arXiv などからダウンロードした PDF
- 大きすぎるファイル
- 一時生成物、キャッシュ、中間ファイル

`.gitignore` は、「Git で記録しないファイルやフォルダ」を指定する設定ファイルです。  
この方針に合わせて、`.gitignore` には最低限の除外設定が入っています。  
迷ったら「あとで自分や他人が再取得できるものは Git に入れない」と考えると判断しやすいです。

## 5. commit メッセージの書き方

commit メッセージは、短くてもよいので「何を変えたか」がわかるように書きます。

例:

- `解析スクリプトを追加`
- `発表スライドを更新`
- `参考文献リストを整理`
- `図3の元データを追加`

## 6. まず守る運用ルール

- 最初は `main` だけを使う
- 作業の区切りごとに commit する
- 1 日の終わりか、一区切りのたびに `git push` する
- `git status` を見てから commit する
- 何かわからない操作を、検索してそのまま試さない

## 7. よくあるミス

### 生データをそのまま入れてしまう

生データは `data/raw/` に置き、原則として GitHub に上げません。

### ダウンロードした PDF を大量に入れてしまう

配布 PDF は必要ならローカル保存にとどめ、GitHub には上げない方が安全です。

### ノートブックや出力結果をまとめて大量に commit してしまう

変更が大きすぎると後で見返しにくくなります。  
作業の区切りごとに小さく commit してください。

## 8. 困ったとき

競合解消、branch 操作、履歴の巻き戻しなどは、初心者には事故が起きやすい操作です。  
必要になるまでは無理に使わず、研究室の教員や先輩に相談してください。
