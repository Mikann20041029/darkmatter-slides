# バブルテンプレートが空だった原因 — 工程追跡による特定と修正

診断: `code/audit_bubble_pipeline.py`(構築の各工程で「バブル矩形の内 vs 外」を測る)

## 修正前: どこでバブルが消えていたか(Bin3 = 4.31 GeV)

| 工程 | 枠内−枠外 | 残存率 |
|---|---|---|
| 0. 生カウント | **+0.315** | 100% |
| 1. 等方背景を減算 | +0.315 | 100% |
| **2. GALPROP+GCE を減算** | **+0.063** | **20%** |

**GALPROP の差し引きがバブルの光の 80% を吸い取っていた**(A_gas=1.615, A_ics=1.85 と過剰スケール)。

## 特定した3つの原因と修正

### ① 構築フィットの成分が足りない(Totani §3.1「他のモデル成分と一緒にフィット」)
旧: {gas, ICS, GCE, flat, **自由offset**} のみ。iso と Loop I が無いため、その分を gas/ICS が
肩代わりして過剰スケールし、副作用でバブルを吸収。さらに**自由 offset は等方成分と数学的に
縮退**しており A_iso を 0 に潰していた(Totani のモデルに offset は存在しない)。
→ **iso と Loop I(2シェル)を追加し、offset を廃止**。

### ② 等方背景の事前減算が廃止済み手法(METHOD_DECISIONS #11)
旧: `subtract_isotropic()` で |b|>50° の平均を先に一律減算。これは「iso を |b|>=50 平均で固定」
= **廃止済み**手法。しかも基準域 |b|>50° の **36.7%** がバブル矩形と重なるため、
**バブルの光を混ぜて引いていた**。
→ **事前減算を廃止**し、iso は構築フィット内で他成分と同時に決める。

### ③ 正負分割と平滑化の順序が逆(Totani §3.1)
論文: バブル画像(平坦テンプレ+残差)→ フラックス変換 → **σ=1°で平滑化** → **その後**正負に分割。
旧実装: **先に正負へ分割 → 各々を平滑化**。0.125° では1画素のポアソン雑音(σ≈√0.87≈0.93)が
バブル信号(≈0.31)より大きいため、先に分けると雑音の正側・負側を機械的に振り分けるだけになり、
**両テンプレとも「雑音の絶対値マップ」= ほぼ一様**に化けていた。
→ **平滑化を先に行い、その後で正負に分割**。

## 追加の判断: 銀河面(|b|<10°)を構築フィットから外す

銀河面はカウントが桁違いに多く Poisson 尤度を支配するため、GALPROP の緯度形状のズレが
A_gas を吊り上げ、高緯度(バブル)で引きすぎになる。修正後の公平比較:

| | **銀河面 除外** | 銀河面 込み |
|---|---|---|
| A_gas | **1.099**(物理値≈1) | 1.668(過剰) |
| A_iso | **0.123**(生存) | 0(死) |
| バブル正 枠内割合 | **61.7%** | 57.7% |
| バブル正 in/out | **3.27** | 2.77 |
| バブル負 枠内割合 | **10.8%**(枠外に寄る=論文通り) | 30.9%(一様寄り) |

全指標で除外が優位。**METHOD_DECISIONS #3 は「銀河面込み」を現行としていたが、それは
本書の3バグを抱えたままの判断だった**ため、v14 で全13ビン再評価する。
